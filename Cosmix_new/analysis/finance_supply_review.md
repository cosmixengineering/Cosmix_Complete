## Severity-Ranked Findings

P1 = release blocker or materially incorrect/unauthorized financial or quantity outcome. P2 = broken workflow, invalid model state or misleading reporting. Runtime findings are inferred from traced source; the parent build result is separately attributed.

### P1-D01: Procurement, GRN and invoicing consequential APIs enforce authentication only

An authenticated tenant user can reach supplier creation, PO creation/approval, GRN creation and invoice/payment actions without the corresponding domain action permission or module gate. PO approval has no reviewer identity, amount limit or decision evidence. Contrast the actual named posting permission at `src/NOIR.Web/Endpoints/JournalEntryEndpoints.cs:141` with `src/NOIR.Web/Endpoints/ProcurementEndpoints.cs:43` and `src/NOIR.Web/Endpoints/ProcurementEndpoints.cs:94`; GRN `src/NOIR.Web/Endpoints/FulfillmentEndpoints.cs:70`; invoice/payment `src/NOIR.Web/Endpoints/InvoicingEndpoints.cs:11` and `src/NOIR.Web/Endpoints/InvoicingEndpoints.cs:70`. Shared tenant filtering exists; this finding is missing business authorization, not a claim that tenant filters are absent. Violates PR05 authority checks and Accounts approval requirements: `../analysis/detailed_srs.txt:535`, `../analysis/detailed_srs.txt:1194`.

### P1-D02: Receipt confirmation can commit partial stock while returning failure

Trigger: a StockOut receipt has two items; the first has sufficient stock, the second does not. Confirmation changes the header first, then the first movement calls a logger which saves the shared DbContext; the second returns a validation failure without rollback. The database can retain a Confirmed header, first deduction and first movement while omitting the second deduction. Retry is then blocked by the Confirmed state. Evidence: `src/NOIR.Application/Features/Inventory/Commands/ConfirmInventoryReceipt/ConfirmInventoryReceiptCommandHandler.cs:48`, `src/NOIR.Application/Features/Inventory/Commands/ConfirmInventoryReceipt/ConfirmInventoryReceiptCommandHandler.cs:79`, `src/NOIR.Application/Features/Inventory/Commands/ConfirmInventoryReceipt/ConfirmInventoryReceiptCommandHandler.cs:95`, `src/NOIR.Infrastructure/Services/Inventory/InventoryMovementLogger.cs:52`, shared UoW `src/NOIR.Infrastructure/DependencyInjection.cs:96`. No outer transaction is registered in `src/NOIR.Web/Program.cs:207` or opened in this handler; transaction support is explicit at `src/NOIR.Infrastructure/Persistence/ApplicationDbContext.cs:292`. This violates the authorized receipt/movement outcome in INV03.

### P1-D06: Material issue bypasses order lifecycle and can invalidate requirement quantities

IssueMaterial loads the order/item without checking Draft, Released, InProgress, Completed or Cancelled status. Evidence: `src/NOIR.Application/Features/Manufacturing/Commands/IssueMaterial/IssueMaterialCommandHandler.cs:32`, `src/NOIR.Domain/Entities/Manufacturing/ProductionOrderItem.cs:69`, `src/NOIR.Application/Features/Manufacturing/Commands/UpdateProductionOrder/UpdateProductionOrderCommandHandler.cs:83`, `src/NOIR.Domain/Entities/Manufacturing/ProductionOrderItem.cs:55`. ### P1-D07: Additive production and stock operations have no request deduplication

### P1-D08: Concurrent journal edits can bypass the Draft-only posting invariant

Two requests can load the same Draft entry. One posts its balanced lines; the other subsequently inserts an additional debit line based on its earlier Draft check. Neither a version precondition nor parent concurrency token makes the line edit fail after posting, so the posted entry can become unbalanced. Evidence: Draft check and insertion `src/NOIR.Application/Features/Accounting/Commands/AddJournalLine/AddJournalLineCommandHandler.cs:42` and `src/NOIR.Application/Features/Accounting/Commands/AddJournalLine/AddJournalLineCommandHandler.cs:68`; posting `src/NOIR.Application/Features/Accounting/Commands/PostJournalEntry/PostJournalEntryCommandHandler.cs:42`; header/line mappings `src/NOIR.Infrastructure/Persistence/Configurations/JournalEntryConfiguration.cs:6`, `src/NOIR.Infrastructure/Persistence/Configurations/JournalLineConfiguration.cs:6`; shared base has timestamps but no concurrency token, `src/NOIR.Infrastructure/Persistence/Configurations/_Shared/BaseEntityConfiguration.cs:12`. Production counters have the same unprotected read/increment/save pattern and can lose concurrent increments. Existing commerce stock explicitly has a token, `src/NOIR.Domain/Entities/Product/ProductVariant.cs:18`. No race was executed.

### The Commerce-to-ERP Disconnect

The stock model reused from commerce is product **variant + integer count**, with movements keyed to that variant and a free-text reference. Decimal material quantities cannot be mapped into the integer counter by assumption; approved units, conversion precision, locations, reservation/negative-stock policy and valuation must be settled.
