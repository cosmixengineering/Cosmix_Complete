# Continuous verification

Backend CI restores locked dependencies, builds and runs the safe regression suite, audits NuGet advisories, then separately migrates a fresh guarded Windows LocalDB database and exercises SQL boundaries. One-shot legacy business-data acceptance fixtures are excluded. The SQL job cannot use an arbitrary company database. Existing retained-clone integration/concurrency suites remain separately runnable with their explicit guarded connection variable; they are not claimed as executed by the empty-schema CI job.

Web CI runs lint, formatting, TypeScript/Vite build and the npm high/critical advisory gate. Mobile CI runs lint, formatting, TypeScript, release configuration tests, npm audit, Android debug assembly/lint and a negative production-signing guard. Production signing keys never enter ordinary pull-request builds.

All three repositories scan Git history with checksum-pinned Gitleaks and fully redacted reports. Exact reviewed public storage labels and synthetic idempotency identifiers are allowlisted; application source remains scanned. Generated dependency/build directories are excluded. The local ignored web `.env` has a browser Maps key; it is not committed in the current tree, and its Google API/referrer restrictions require owner verification. Do not move it into Git or imply that frontend keys are confidential. A static test JWT signing key was replaced with a fresh per-run random key. The actual history scan still reports historical Maps-key occurrences in backend/web and legacy synthetic fixture markers. Those history scans currently fail; they are not waived or claimed clean. Confirm the historical key's revocation/replacement and API/referrer restrictions with its owner before accepting the release. Do not suppress real findings or rewrite shared history casually. Mobile history scan passed.

CodeQL is enabled only when repository variable `COSMIX_CODEQL_ENABLED=true` is set after confirming the private-repository entitlement. This opt-in means CodeQL has not yet run here. Its mobile analysis is JavaScript/TypeScript; Android lint covers the native build, and neither substitutes for a native security assessment. A formal assessment must still test authorization, sensitive export/storage, MFA recovery, bank/reconciliation concurrency and physical biometric spoof cases on an approved deployment.

The shared-IP transport test runs 40 authenticated identities and 120 concurrent requests against the real rate-limit middleware. It verifies independent employee quotas, case-insensitive routes, 429/Retry-After and isolation of face/attendance quotas. It is not a production throughput benchmark or a real network camera test. Multi-instance quotas still need a shared trusted gateway strategy.

Local dependency audit after patching found no high/critical advisories. The mobile development CLI retains four low-severity deepmerge-related advisory entries; npm's suggested fix downgrades the CLI across major versions and is intentionally not forced into the RN 0.87 build. Track the upstream fix and re-audit in CI. No formal-security sign-off is implied by these checks.
