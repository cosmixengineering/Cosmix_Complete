## Verified Behavior

| Controlled key failure | Exclusive key handle blocks actual reads and writes; raw-file probe proves the failure; failed writes allocate no objects; release restores reads/writes |

| Error contract | Expected failures retain `private_file_storage_unavailable`, status 503, a generic message and no inner exception |

## Initial Harness Failure and Correction

The first execution compiled and passed 18 of 20 scenarios, with 148 parent
assertions and 7 child assertions. Both ACL scenarios failed on recovery.
Read-back of the test-only directory ACLs showed the injected deny/broad rules
were still present after `SetAccessControl(original)`. The saved ACL object had
no modified access section to persist; this was a harness restoration bug.

Restoring a fresh `DirectorySecurity` from the saved binary descriptor with
`AccessControlSections.Access` persisted the DACL. The helper now verifies
the restored rules and inheritance-protection state on disk. The two original
test directories were restored to one current-user FullControl rule; no original
test objects or logs were deleted. A wholly new root rerun passed every case
against the identical product DLLs. No storage safety assertion was removed and
no product fix was made.
