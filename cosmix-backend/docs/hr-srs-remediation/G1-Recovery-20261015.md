## Repaired Boundary

Before the change, `AttendanceOperation.WriteAsync` returned an existing receipt
before entering recovery creation's callback. Current session/fixed-role checks
still ran, but the callback's parent lookup, submission-proof verification,
beneficiary/requester exclusion and leave-cancellation checks were bypassed.
Thus a receipt could return success after its leave entered cancellation review,
after approved cancellation, or when its parent evidence was no longer valid.

`RecoveryParentAsync` now supplies the same parent validation to both the
creation callback and `beforeReplay`, within the existing authorization
transaction. Missing leave remains 404; cancellation/ineligible approval is
409; self-action remains 403. Valid receipt replay does not rerun date/quota
creation validation against its own already-recorded commitment. No historical
commitment is deleted or marked fulfilled.

   fulfil a commitment or only additional unallocated work; treatment of partial
   completion, corrections and cancellation; and whether fulfilment merely
   closes the obligation or earns a specified leave/pay effect. KPI benefit
   thresholds, units, exclusivity and deciding authority need separate evidence.
2. Implement a real repository over the existing generic approval entities and
   protected snapshots. Bind employee, leave, commitment, policy version, source
   session revision and exact intervals. Validate current authority and parent
   evidence on submission, decision and replay inside AttendanceOperation.
3. Add the recovery reader to every competing OT, make-up, early-credit and
   ordinary-pay allocation path, including the reverse creation order and
   cross-business-date physical overlaps. Existing readers do not discover
   arbitrary new recovery approvals automatically. Establish one durable effect
   after receipt expiry and reject stale source corrections; do not silently
   undo retained work or money.
4. Wire the repository, service, actual API and DI together under parent-owned
   integration; run standalone failure-first checks and authenticated SQL race,
   rollback/restart and source-correction acceptance before enabling the path.
